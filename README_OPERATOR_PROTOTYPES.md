# Schumann Virtual Operator Computer — cross-platform external operator candidates

**Development scope:** a conservative prototype that exercises two **independent** GitHub-hosted environments. This branch stacks on the synthetic-video evidence branch. It does **not** create a persistent Windows virtual desktop or log in to Microsoft Stream, install Power BI Desktop, circumvent access controls, or solve software incompatibility in general.

## Architecture

| Type | Runner | Allowed operation | Evidence |
| --- | --- | --- | --- |
| `windows.compatibility` | `windows-2025` | Python/PowerShell presence; cautiously inspect familiar Power BI Desktop executable paths without running it | JSON boolean capabilities |
| `linux.synthetic_video` | `ubuntu-24.04` | Generate **original** 3-second FFmpeg test pattern with sine-tone audio and verify technical metadata using existing read-only media analyzer | JSON hash/duration/audio/frame report |

The `operator_contract.py` module defines two **fixed** request types with `execution_budget=1`, `authorization=synthetic-read-only`, and precise result types. The verifier rejects unknown operators, arbitrary URLs/commands, unexpected fields, synthetic/privilege escalation, invalid metrics, tampering, and cross-platform type substitutions. JSON is bounded and parsed without invoking shell input.

The generated evidence is **not a digital signature or provenance proof**: a party that can edit the report and recompute its hash can forge it. It is a useful reproducible consistency check only. The Linux operator does not verify every video frame, or prove the clip was originally generated by this process. The Windows operator does not verify access to an interactive graphical session, a Power BI Desktop installation, a Power BI license, or application usability.

## Relationship to M45 / CVOC

CVOC-ST02 and CVOC-ST04 currently support ST30, ST38, ST43, ST44 and ST47. **They do not currently recognize `windows.compatibility` or `linux.synthetic_video`.** This branch is an **external operator candidate**; its `native_cvoc_verified` and `cross_component_verified` flags are deliberately always false. Typed integration with CVOC will require an independently reviewed extension and native verification rather than merely renaming a manifest.

M45 checkpoint continuation is out of scope here. GitHub-hosted runners are temporary machines, not a persistent computer. A later, reviewed scheduler could submit bounded requests and inspect their JSON artifacts, but must not automatically refresh sessions, dispatch unbounded jobs, rewrite protected state, or exceed authorized resources.

## Local verification

```sh
python3 -m unittest discover -s scripts -p 'test_operator_contract.py' -v
python3 -m unittest discover -s scripts -p 'test_cvoc_media_evidence.py' -v
python3 scripts/operator_linux_media_probe.py --output-dir artifacts/linux_operator
python3 scripts/operator_contract.py artifacts/linux_operator/request.json artifacts/linux_operator/report.json
```

Last two commands require Linux and FFmpeg. The Windows probe must run on Windows (it rejects a non-Windows host).

## GitHub Actions

`.github/workflows/schumann-cross-platform-operators.yml` runs **only on PR changes or an explicit manual dispatch**. Its jobs use GitHub-hosted `windows-2025` and `ubuntu-24.04` and `contents: read` permission, no secrets, no institution links, no Microsoft 365 credentials, and no scheduled jobs. The Linux job obtains FFmpeg and FFprobe from a pinned `ffmpeg-binaries==1.1.0` platform wheel with an independently checked SHA-256 digest (rather than the Ubuntu apt mirror, which twice timed out). This is a 60 MB third-party executable dependency; its hash checks integrity of the downloaded artifact, not whether the binaries are free from vulnerabilities. If the wheel is inaccessible, CI fails closed. Review the binary supplier before future promotion. Only **non-sensitive JSON test reports** are retained for one day. The short synthetic MP4 remains on the disposable runner, and no audio/video is published by this workflow.

**Review gates:** this branch and its stacked PR must receive independent review before merging. CI success would show only that the synthetic proof of concept executes on both hosted OS environments. Do not promote to course capture or Power BI production without separate consent, authorization, secure runner design, and an actual end-to-end application test.

## Three independent checkpoints

1. **Typed-interface unit tests** pass on Windows and Linux.
2. **Hosted runner capability/FFmpeg jobs** pass, producing well-typed JSON reports.
3. **Real desktop application, Microsoft Stream playback, school authorization, persistent state, and secure cross-repo orchestration** remain unimplemented and must not be reported as complete.
